# 权重检索

**让 Cortico 记住有用的事，找回当时的原话，并说清楚是谁的经历。**

这是原“分区权重记忆”的更新版。页面名称改了，原来的包名、记忆数据位置和配置名称保持兼容。

它是给 Cortico 使用的 Persona / Memory（bot）扩展，自带基础 Persona、SQLite 存储和操作页面。它不是独立聊天软件，也不能作为 World 加到任意一个现有 Persona 上。

[下载 0.2.6](https://github.com/Kpect10086/Cortico-Weighted-Memory/releases/tag/v0.2.6) · [更新记录](CHANGELOG.md) · [技术参考](docs/technical-reference.md)

## 它能做什么

举个例子：

> 一位访客说：“我替你保管花盆，周六还给你。”

系统可以把这段话整理成一条带来源的记忆，保留“访客说的”和“归还约定”。以后问起花盆，可以查这条记忆，再打开原始发言核对。它不应该把访客的话变成 bot 自己的经历。

这里的“应该”是规则和工具提供的约束，不是准确率保证。模型仍可能理解错误，所以页面保留了查原文、审核和纠正功能。

| 功能 | 用最简单的话解释 |
| --- | --- |
| 按事情整理记忆 | 把同一件事的多条消息合起来，不要求每句话都存成一条记忆。 |
| 按会话分开 | 不同会话的资料分开保存，检索遵守当前会话范围；共享核心摘要有单独规则。 |
| 给记忆分配重要程度 | 用 1–12 档权重帮助选择哪些资料值得进入有限的上下文。 |
| 查记忆，也查原文 | 先找整理后的摘要，没找到时可以换词查来源片段。 |
| 摘要和来源互相跳转 | 从摘要看原话，也能从来源找到关联的已通过记忆。 |
| 保留人物和时间 | 原始说话人、会话和接收时间可回查；事情发生时间不知道就保持未知。 |
| 审核、纠正和回退 | 先确认候选，再让它参与普通回忆；改错保留版本和操作记录。 |
| 批量管理 | 可以批量通过、拒绝或归档，也可以合并、拆分记忆。 |
| 双向排序 | 按记录时间新到旧或旧到新，按重要性高到低或低到高。 |
| 搜索范围说明 | 告诉你查了哪个会话、哪段记录时间、匹配多少，还有没有下一页或截断。 |
| 导入与导出 | 支持 JSON、Markdown、SQLite；便于备份、查看和迁移。 |

## “权重”是什么意思

权重表示**这条记忆有多值得保留和优先使用**。

- 1–9 档用于一般事情，结合遗忘损失、关系意义和以后是否还找得回来判断。
- 10–12 档留给有明确依据、影响重大且持续的事情，需要操作员审核。
- 默认单句记忆需要达到 8 档才允许通过；可以在配置里调整。
- 权重不是可信度，也不是保留天数。高权重不代表内容一定真实，也不保证每一轮都进入上下文。

## 新的检索联动怎么用

打开 Cortico 左侧的 **权重检索**，在“权重检索 · 记忆与原文”区域：

1. 输入关键词、编号或一小段原话，填写要查的会话。`main` 表示主会话；其他会话可以参照下方记录显示的会话标识。
2. 先选择“已通过记忆”。需要时设置记录日期起止，再点“检索记忆与原文”。
3. 没找到时，换关键词或选择“原始来源片段”。这里按输入的完整字面片段查找，不会理解所有同义说法。
4. 点“核对原话”，查看原始发言、说话人和接收时间。原话较多时可以继续翻页。
5. 来源结果里的“查看关联记忆”可以跳到下方管理区；审核、纠正或停用后，下一次读取会更新关联。

记忆、来源、管理页面和模型工具都用同一份数据库，不需要手工在两套记忆之间同步。

**“没找到”只表示本次范围和查法没有命中，不能证明事情没发生。**

同样，“查询完成”表示这次数据库条件查询完成，不表示所有历史都已采集、所有说法都已搜索。搜索按记录时间筛选，不是按事情实际发生的日期筛选；未知历史完整性会明确显示出来。

## 与自己无关的事会怎样

整理规则要求默认略过与主体无关的第三方交流，不因为“同处群聊”“名字相似”就把别人的事情记成自己的。只有和主体经历、关系、偏好或后续任务有实际关联的内容，才值得提炼成长期记忆。

**略过长期记忆，不等于删除原始聊天。** 本插件保留已采集的原始资料供追溯，升级也不会自动清理旧原文。需要清理历史时，应另行确认范围并备份。

关联性和人物归属仍由模型判断。插件能保留证据、限制会话和要求审核，不能保证模型永远判断正确。

## “审核”和“训练”有什么区别

页面里有三件不同的事：

| 名称 | 作用 |
| --- | --- |
| 记忆通过审核 | 允许这条摘要参与普通记忆检索和上下文选择。 |
| 内容过滤 | 如果配置了过滤服务，先处理不适合展示或注入的内容；这不等于认定事实正确。 |
| 训练授权 | 单独允许这条记忆的当前版本被导出成训练素材。 |

普通候选默认待审，“普通记忆自动通过”默认关闭。开启自动通过后，符合条件的一般候选可以自动生效；核心身份、非常规高权重、捏造内容等仍有额外限制。

**正常记忆和回忆不需要训练授权。** 目前“训练”只有单独授权和素材导出功能，没有接入模型训练流程。点“允许用于训练”不会启动训练，也不会修改模型。撤回授权只影响后续导出，已经下载的文件不会自动收回。

## 安装 0.2.6

需要：

- Cortico **0.2.6 / Bot API 7**。本版本按这个公开框架版本验证。
- Node.js **22.16 或更新版本**，推荐 Node.js 24。
- Git，供自带基础 Persona 管理文件工作区。
- 一条可用的模型连接。记忆整理等模型任务会产生模型用量；SQLite 检索本身不调用模型。

### 从 GitHub 下载

1. 到 [Release 下载页](https://github.com/Kpect10086/Cortico-Weighted-Memory/releases/tag/v0.2.6)，下载更方便解压的 `weighted-retrieval-0.2.6.zip`，或下载 `cortico-bot-weighted-memory-0.2.6.tgz`。
2. 解压，找到有 `package.json`、`index.ts` 和 `dist` 的 `package` 文件夹，放到准备长期保留的位置。
3. 在 Cortico 的“扩展”页选择 Persona / Memory，通过“手动安装”的本机目录入口选择这个文件夹。
4. 为部署选择 `cortico-bot-weighted-memory`，然后重启该部署。部署文件使用的 bot 值是这个包名。
5. 配好模型连接，打开“权重检索”页面。QQ、游戏等 World 按需要另外安装，本包默认只声明控制台。

下载包已经带编译好的页面，无需自己构建。本次 0.2.6 通过 GitHub Release 提供，直接按 npm 包名安装时应先检查 npm 上的实际版本，不能把旧版本当成此次更新。

### 升级已有版本

先备份当前部署的 workspace 和一致的 SQLite 数据库，再更新插件并重启。运行中的 SQLite 可能使用 WAL，不能只复制一个正在写入的 `.db` 文件来代替一致备份；可以使用现有 SQLite 全量导出或在线备份。

0.2.6 保留包名 `cortico-bot-weighted-memory`、bot ID `vanilla-memory`、面板 ID `weighted-memory`、`weightedMemory.*` 配置键和 `vanilla-memory.db` 数据位置。不要同时启用同 ID 的 `cortico-bot-vanilla-memory`。

包里没有私人设定、数据库或账号。不要用包里的文件覆盖自己的 workspace。旧格式资料的重整迁移请先在备份上演练，步骤见[技术参考](docs/technical-reference.md)。

## 第一次使用

- **想保留重要的事**：让模型按规则整理候选，或在“快速添加与导出”里手工添加，再审核。
- **想找旧事**：先检索已通过记忆，再按需查来源、核对原话。
- **想改错**：打开对应记录，填写理由后纠正；新版本需要重新审核。
- **想备份**：选择导出格式和范围，每次生成一个下载文件。
- **只想正常聊天**：训练授权保持未授权即可，不影响普通记忆。

可选的内容过滤地址默认留空。填写外部过滤地址后，相关正文会送往该地址处理；服务失败时不会放行对应正文。模型连接同样可能收到检索后选入上下文的资料，请按自己的部署需求配置。

## 当前限制

- 使用 SQLite 全文检索和字面匹配，没有向量服务依赖；仍可能漏掉不同说法，也可能返回无关候选。
- 原始资料、待审摘要和已通过记忆用途不同，原文不是已确认事实。
- 不保证“永不遗忘”“永远分清人物”或“没有幻觉”，也不保证所有历史都能查回。
- 自动整理、会话范围、预算和审核状态都会影响最终可用的记忆。
- 不附带 QQ 客户端、模型账号、第三方过滤服务或训练服务。
- 0.2.5 的跨平台修复已保留。本地验证与 GitHub Actions 的各平台结果分开记录；最终以本次版本的检查结果为准。
